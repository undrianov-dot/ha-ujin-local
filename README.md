# UJIN Local for Home Assistant

Экспериментальная кастомная интеграция Home Assistant для локальной работы с
устройствами UJIN/Sapfir без облака. Интеграция принимает JSON-пакеты по UDP
на порту `30300` и отправляет локальные команды управления.

> Проект не связан с UJIN и не является официальной интеграцией производителя.

## Поддерживаемые устройства

- `ujin-potato-trm-m1` — термостат;
- `ujin-potato-ld-m1` и `dinrelay_m4` — контроллеры протечки/реле;
- старый формат пакетов Sapfir с оболочкой `{"header": ...}`.

Другие устройства могут появиться как набор диагностических сенсоров. Их
команды управления нужно проверять отдельно.

## Установка через HACS

1. В HACS откройте **Integrations**.
2. В меню выберите **Custom repositories**.
3. Вставьте адрес этого GitHub-репозитория и выберите тип **Integration**.
4. Найдите **UJIN Local**, установите интеграцию и перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
6. Выберите **UJIN Local** и оставьте порт `30300`.

## Ручная установка

Скопируйте каталог `custom_components/ujin_local` в
`/config/custom_components/ujin_local`, перезапустите Home Assistant и добавьте
интеграцию через интерфейс.

## Требования к сети

Home Assistant должен получать широковещательные UDP-пакеты устройств. Для
Home Assistant Container обычно требуется режим сети `host`; альтернативно
нужно обеспечить доставку UDP `30300` в контейнер.

## Безопасность и ограничения

- Токены устройств хранятся только в памяти и удаляются из диагностики.
- IP-адрес, токен, модель и `last_seen` сохраняются в стандартных данных
  config entry, чтобы устройства могли восстановиться после перезапуска.
  Токены не включаются в диагностику.
- Уставка термостата использует найденное в пакете поле; резервное поле —
  `reg-term`, известное по локальному протоколу UJIN/Sapfir.
- Изменение уставки ожидает ответный UDP-пакет с тем же `uniq_id`; при
  отсутствии подтверждения за 5 секунд Home Assistant получает явную ошибку.
- Переключатель водяного клапана создается только после получения известного
  сигнала клапана. Интеграция не угадывает наличие исполнительного механизма.
- Перед использованием в защите от протечек физически проверьте соответствие
  состояний «открыто/закрыто» и работу штатной автоматики.
- Сущности становятся `unavailable`, если от устройства нет UDP-пакетов
  5 минут. Атрибут `last_seen` содержит timezone-aware время последнего
  принятого пакета; проверка доступности обновляется каждые 30 секунд.

## Диагностика

Если устройство не распознано, скачайте диагностику записи интеграции в Home
Assistant. Неизвестные простые поля автоматически публикуются как сенсоры, а
секретные поля и токены в диагностику не попадают. Текущая и установленная
температуры берутся из UDP-полей устройства (обычно `term` и `reg-term`), а
не из зашитых значений. Для `dinrelay_m4` реле `rele1` отображается как
переключатель клапана.

## Состояние проекта

Версия `0.1.0` предназначена для проверки на реальном оборудовании. Нужно
подтвердить на конкретной прошивке точные поля ответа после изменения
уставки и семантику `rele1`/датчика протечки перед автоматическим перекрытием.
