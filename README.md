# UJIN Local for Home Assistant

Экспериментальная локальная интеграция Home Assistant для устройств UJIN/Sapfir
без облака. Интеграция принимает JSON-пакеты по UDP на порту `30300` и отправляет
локальные команды управления.

> Проект не связан с UJIN и не является официальной интеграцией производителя.

## Поддерживаемые устройства

- `ujin-potato-trm-m1` — термостат;
- `ujin-potato-ld-m1` — датчик/контроллер протечки;
- `dinrelay_m4` — двухканальное реле;
- старые устройства Sapfir с оболочкой `{"header": ...}`.

Версия 0.2 использует стабильный набор сущностей. Частичные UDP-пакеты больше не
создают случайные сенсоры: для термостатов публикуются температура, CO₂, IAQ и
освещённость, для DIN-реле — два переключателя и два дискретных входа. Остальные
служебные поля сохраняются в диагностике.

## Установка через HACS

1. В HACS откройте **Integrations**.
2. В меню выберите **Custom repositories**.
3. Добавьте URL этого репозитория с типом **Integration**.
4. Установите **UJIN Local** и перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
6. Выберите **UJIN Local** и оставьте порт `30300`.

Изменить порт после установки можно через действие **Перенастроить** в меню
настроек интеграции. Удалять запись для этого не требуется, поэтому сохранённые
IP-адреса, токены и `last_seen` устройств не теряются.

## Обновление с 0.1

После обновления и перезагрузки интеграция автоматически отключит шумные
служебные сенсоры версии 0.1. Они не удаляются и при необходимости могут быть
включены вручную в реестре сущностей.

## Сеть

Home Assistant должен получать широковещательные UDP-пакеты устройств. Для
Home Assistant Container обычно требуется режим сети `host`; иначе необходимо
доставить UDP `30300` в контейнер.

## Управление и ограничения

- DIN-реле управляется сигналами `rele1` и `rele2`.
- Для термостатов уставка изменяется через стандартный сервис
  `climate.set_temperature`. Команда отправляется только после обнаружения
  устройством поддерживаемого ключа уставки и считается успешной после
  ответного UDP-пакета с тем же `uniq_id`.
- Изменение состояния или уставки ожидает ответ устройства с тем же `uniq_id`.
  Если подтверждение не приходит за 5 секунд, Home Assistant показывает ошибку.
- Целевая температура доступна только после того, как термостат сам передал
  поддерживаемое поле уставки. Интеграция не угадывает имя команды.
- Переключатель водяного клапана создаётся только после получения реального
  сигнала клапана от устройства.
- IP-адрес, токен, модель и время последнего пакета сохраняются в данных записи
  интеграции для восстановления после перезапуска.
- Перед использованием управления отоплением или водой физически проверьте
  соответствие состояний устройству и штатной автоматике.

## Диагностика

В карточке интеграции Home Assistant можно скачать диагностику. Токены и пароли
в неё не попадают; неизвестные сигналы сохраняются для анализа протокола.
Если свежих UDP-пакетов нет, сущности продолжают показывать последнее известное
значение; время последнего пакета доступно в атрибуте `last_seen`.
